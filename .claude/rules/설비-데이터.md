# 설비 데이터 규칙 (db/, lib/data.ts, lib/db.ts를 다룰 때)

- 데이터는 로컬 PostgreSQL(`iems` DB)의 `equipment_events` 테이블 하나가 유일한 기준이다. 화면에서 값을 입력·수정·삭제하지 않는다 (조회 전용).
- 새 샘플이 필요하면 `npm run db:seed`로 다시 만든다 (`db/seed.ts`가 TRUNCATE 후 재삽입한다). 직접 `INSERT`/`UPDATE`로 손대지 않는다.
- 스냅샷(현재 상태)과 이력을 별도 테이블로 나누지 않는다 — 라인·설비별 최신 1건 조회(`distinct on`)로 스냅샷을, `status <> '정상'` 필터로 이력을 같은 테이블에서 얻는다.
- 상태가 멈춤·알람인 레코드는 원인(cause)이 반드시 있어야 한다 (100자 이내) — DB `check` 제약(`cause_matches_status`)으로 강제된다.
- 상태가 알람인 레코드는 조치 상태(action_status)가 반드시 있어야 한다 (확인전/확인중/조치완료/조치불가 추가 확인 필요) — DB `check` 제약(`action_status_only_for_alarm`)으로 강제된다.
- 비고(note)는 150자 이내다.
- 스키마를 바꿀 때는 `db/migrations/`에 새 SQL 파일을 추가한다 (기존 마이그레이션 파일은 수정하지 않는다).
- 점검자 입력·OK/NG 판정·저장 기능은 이 프로젝트 범위에 없다 — DB는 항상 읽기 전용으로 화면에 제공된다.
- 실 설비/PLC, 외부(클라우드) DB·API는 연동하지 않는다. 이 기기에서 직접 실행하는 로컬 PostgreSQL만 사용한다.
